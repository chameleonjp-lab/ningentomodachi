## 3. Phase 0（P0）：並列化前に固定する共通契約

### P1 実装開始の厳密なゲート

P0 の準備と契約レビューが完了しただけでは、P1 の A/B/C/D 並列実装へ進まない。P0 の PR を本人がマージし、その結果の新しい `main` の commit SHA を親が検証して共通基点として記録した後、全担当が同一 SHA を基点としていることを確認して初めて P1 を開始する。エージェントはマージしない。P0 PR の head SHA、マージ前 main SHA、ローカルに残る古い main を代用しない。

P0 の本人マージ前に B/C/D が行えるのは、読取調査、素材検証結果の整理、fixture の設計、契約へのコメントだけである。P1 の製品コード・テストコード実装、共有ファイルの先行変更、古い main からの並列実装開始は行わない。A も P0 の基盤以外の A1 以降へは進まない。P1 に渡す基点は親が確認する将来の commit 値であり、計画作成時に架空の SHA を記載しない。

### 3.2 唯一の状態所有者

- A：HP、ダメージ、撃破台帳、熱量、技の抽選・発動・終了、相殺消費、車命中の 50 ダメージ、車の耐久・再発射可否、損壊台帳、採点時計、ゲーム進行、結果確定。
- B：素材と検証済み技メタデータ、クリップの視覚再生。A に clip ID と技の定義を提供する。描画側の `finished` 通知から HP・回復・次敵・冷却を確定しない。
- C：位置・向き・移動・車の運動・空間接触候補。A に候補を返すが、候補に「適用済みダメージ」を持たせない。車の速度などは C、車ダメージの成立と損壊採点は A。
- D：操作要求と表示。HP バーの赤区間・粒子の消滅は表示完了であり、HP 変化・死亡・回復の命令ではない。

空間候補のダメージ量は外部入力として信用しない。A は候補に記された攻撃発動 ID と打撃 ID から、有効区間・現在の戦闘相手・定義済み威力を引き直して確定する。古い runId の入力・イベント・読込完了は破棄する。

### 3.3 時計とフレームの契約

1. ポーズ除外実時間：設定中・背景化・必要な中断時には進めない。冷却の 7/3 毎秒と撃破 1.5 秒・敗北 2 秒の演出期限は、この時計を使う。
2. ゲーム時間：世界のスロー倍率を反映する。攻撃の有効区間、移動、採点上の生存時間・クリア時間に使う初期案。採点時計は結果確定で凍結する。
3. 表示時間：終端確定後も専用演出だけ進められる。敗北後の 2 秒を生存時間に追加しない。熱量も終端時点で凍結する。

固定時間刻みと seed 付き乱数を A が管理する。描画はスナップショットを補間し、30/60/120 fps の描画回数で命中数や乱数消費を増やさない。C は固定刻み内の掃引接触と接触時刻を返し、A が安定した順序に並べる。背景化からの復帰で大きな elapsed を一括投入しない。通常の描画遅延については、検出していない区間を飛ばして後から当たったことにするのでなく、刻みと掃引の連続性を保つ。

1 tick の結線は「D の要求を受信 → A が技・移動状態を決定 → C が B のルート・判定情報から空間を進める → C が候補を返す → A が同時刻単位で解決 → B/C/D が確定スナップショットとイベントを読む」。この順序を `frameLoop.ts` に集約する。B の見た目が追い付くことを戦闘処理の前提にしない。

### 3.4 最小の HP イベント

`HpChanged` は eventId、runId、対象 actorId、原因、発生ゲーム時刻、最大 HP、変更前 HP、変更後 HP、実際に失った HP、攻撃カテゴリまたは車由来、同時刻 batchId を持つ。`Healed` と `ActorDefeated` も同じ順序で一度だけ発行する。

残 HP 10 に 70 が命中しても、HP 表示用の実損失は 10。黒の 70 ダメージでは分母は 700。相殺同値の差分 0 は `ClashResolved` の演出情報のみとし、HP 減少イベントを偽造しない。D はその機体のバーへ粒子を吸収する。回復は A の独立したイベントのみで、粒子の吸収では発生しない。

## 4. 必須条件と暫定案を混ぜない管理

### ユーザー要件として守る条件

- 敵は青・緑・黄・黒の計 4 体、常に 1 対 1。通常 3 体の後に黒。白と通常敵は最大 HP 500、黒は 700。
- 通常敵は色ごと固定のパンチ 4 種・キック 4 種から抽選。黒は既存キック全 19 種のみ、パンチなし。
- 撃破ごとに白を 100 回復し、最大 500。相打ちの敗北を回復で取り消さない。全 4 体撃破でクリア、途中敗北も採点する。
- 短射程ほど 1 技の総威力が高い。連続技は総威力を分配し、打数倍の威力にしない。
- 全機体に同じ 7 回で満タン・3 秒の攻撃ゲージ条件。過熱前も同じ速さで回復し、空になる前の再攻撃を可能にする。
- パンチ・キックの相殺は威力差分のみ。100 対 70 は弱い側へ 30、同値は双方 0。
- 車を蹴って敵に当てると 50 ダメージ。街の損壊は減点で、新しい車利用ボーナスを加えない。
- 撃破スローは実時間 1.5 秒、敗北スローは実時間 2 秒。敗北後は暗転して結果画面。
- HP の緑→赤→粒子吸収→縮小を、双方の正しいバーに表示できるデータを提供する。

### v6 にある暫定案・調整値

次は確定したユーザー判断と表記しない。`rules.ts` / `tuning.ts` に出典と暫定である旨を付け、親の判断待ち項目とする。

- 通常敵の青→緑→黄の順番と具体的な技の割当。パンチ分類の混合技 AcrobaticCombo を抽選から外す案。
- 総威力 `180 / (1 + 有効射程 m)`、各打撃への等分、等確率抽選。
- 発動 1 本を熱 1 とすること、攻撃中は冷えないこと、7 に達した技の終了後から 3 秒ロック、スロー中も実時間冷却、過熱中の移動・ジャンプ、戦闘間の自然冷却のみ。
- 相殺を実接触に限定し、連続技では各打撃の配分威力で比較、同時刻は相殺優先、車は相殺対象外とする案。
- 即時に内部 HP を更新し、赤区間を表示上の残像とすること、同時刻の命中をまとめて敗北優先で解決する順序。
- 車の HP 100・発射で 20 消費、1 発射×1 敵への 50 を 1 回、同一技で同じ車を再発射しないこと、車致死のキック側破壊モーション。
- 敵起因も含めた総損壊の減点、車と街の率の平均、待機敵による画面外追加損壊を計上しないこと。
- スロー倍率 0.25、暗転 0.4 秒、ゲーム時計のスロー追従、スコアの配点式。

技メタデータ、アダプター、テスト fixture の作成を進めるために暫定値を分離して扱うことはできる。ただし、未決定のものを「仕様確定」や最終受入れ完了に変えてはいけない。ジャンプ中攻撃・入力予約、車と身体へ同時に触れる打撃の扱い、複数打撃が同じ接触時刻に競合する扱いなど、資料だけで一意に決められない事項は親へ最小の選択肢と影響を返す。

## 5. 実装する予定のドメイン処理

### 5.1 攻撃抽選とダメージ

発動受理後に一度だけ抽選し、技の途中で再抽選しない。拒否した入力で技発動 ID、熱量、技用乱数を進めない。B の実測有効射程は踏み込みと手足の軌道を含む。ルート移動距離だけを射程の代用にしない。

各技は固定した総ダメージと各打撃の配分を持つ。初期案では等分するが、最後の打撃で端数を調整するなど、全命中の合計が総ダメージに一致する方法を固定する。内部の小数精度を保ち、表示の整数化を戦闘計算へ戻さない。異常な射程、空の打撃列、重複打撃番号、負の配分、有効区間の逆転、実クリップ時間外の有効区間を起動ゲートで拒否する。

### 5.2 相殺と同時命中

候補を接触時刻、安定した打撃 ID の順に正規化し、候補到着順に依存しない。同一時刻内では以下を予定する。

1. 攻撃対攻撃の実接触と双方の有効区間を検証。
2. 未使用の打撃同士を安定順で組み合わせ、その瞬間の配分ダメージを比較。
3. 両打撃を相殺消費として記録。差分を弱い側に 1 回だけ予約。
4. 相殺消費した打撃の身体命中を取り除き、その他の身体命中・車命中をそれぞれ重複排除。
5. 同時刻のダメージを適用し、撃破を一度記録。白が 0 なら敗北を優先。白が生存する場合だけ撃破回復、次敵またはクリアを決定。

1 つの打撃を別の相殺へ再利用しない。通常命中の重複排除キーは発動 ID × 打撃番号 × 相手 ID。相殺が起きた場合の消費状態と矛盾しない台帳を共通で使う。過去に身体命中した打撃が後で別接触を起こした場合も含め、二重適用を避ける規則を fixture で明示する。車への接触と身体への接触の優先は暫定仕様の確認項目であり、実装者が隠れて追加メリットを作らない。

相殺で熱量を返さない。非接触の攻撃、離れた攻撃、違う方向の攻撃は「両者が攻撃中」というだけで相殺しない。車 50 ダメージを相殺式へ混入させない初期案を独立したテストにする。

### 5.3 熱量

機体ごとに `heat`、現在の技、過熱予約、冷却ロック残時間を独立管理する。発動を受理したときだけ `min(7, heat + 1)`。連続技も空振りも相殺も車を蹴る技も、発動は 1 回である。

7 に達した技は最後まで完走。メタデータ上のゲーム時間の終了時点を A が検出し、その時点からポーズ除外実時間で 3 秒のロックを開始する。ロック残時間は熱量と別に保持し、途中で熱量が下がっても早期解除しない。攻撃していない間は通常時と過熱時とも 7/3 毎秒で減る。攻撃・ポーズ・背景化・結果確定後は冷却しない。

5.9→6.9、6→7、6.5→7 の境界を定義し、浮動小数の誤差で過熱判定を逆転させない。熱量 6 で 0.6 秒休むと 4.6、次の発動で 5.6。白と現在の敵の両方を snapshot に出す。敵 AI が熱量条件を迂回して攻撃を開始する経路を作らない。敵交代で白の熱量を 0 に設定しない。

### 5.4 1 対 1、AI、勝敗

通常敵 3 体と最後の黒の存在・撃破状況は A が持ち、戦闘相手 ID は最大 1 つ。待機敵へのダメージ候補、車による先行撃破、待機敵の攻撃要求を拒否する。待機敵からの画面外損壊は計上しない暫定設定を明示する。

敵 AI は C の距離・向き・接近可能性の読取情報から移動・ジャンプ・攻撃の意図を出し、攻撃要求はプレイヤーと同じ検証経路を通す。通常敵の固定 4+4、本数・カテゴリの妥当性を検証。黒の抽選母集団はキック全 19 ID で、パンチコマンドを受けても攻撃できない。未知の防御倍率、色別属性、車利用の特典は追加しない。

進行状態は読込前、開始待ち、非戦闘、戦闘、撃破演出、敗北演出、暗転、結果に分離し、ポーズ理由は直交した集合で管理する。設定を閉じても背景化理由が残っていれば再開しない。終了時は結果を一度だけ latch し、後着イベントで勝敗や採点を変更しない。最終黒との相打ちは撃破 4 でも敗北、クリア時間は null / 未達。黒を倒して生存した場合の HP100 回復後の値を結果へ使うのは v6 の初期処理順として固定検査する。

### 5.5 車と損壊台帳

C のキック接触候補から A が発射の可否を決定し、LaunchId を発行する。C は承認された発射に対して運動を開始する。車ごとの耐久と破壊済みフラグは A が所有し、C の見た目の破壊状態から耐久を再生成しない。

車が現在の敵へ当たった候補を受け、LaunchId × 敵 ID の台帳で 50 を 1 回だけ適用する。HP500→450 を確認する。継続接触、候補再送、異なる描画 fps でも 450 のまま。車撃破も通常の撃破・回復の同一経路に通す。

街と車は開始時の採点対象耐久を分母として保存し、実際の減少量のみ積む。破壊済み残骸・元から壊れた背景物・同じ破壊イベントの再送は減点を増やさない。起因者を記録して総損壊とプレイヤー起因を分ける。対象がないカテゴリの分母 0 は NaN にせず起動時検証または明示した 0 扱いにする。どちらの方針かを親へ提示し、暗黙には採用しない。

### 5.6 採点

スコア計算は純粋関数とし、終了時 snapshot から一度計算する。v6 の暫定式を独立した設定として実装する予定。

- 生存点：`min(600, 生存秒 × 2)`。
- 撃破点：`min(4, 撃破数) × 1000`。
- 残り HP 点：`min(1000, 残り HP × 2)`。
- クリア点：クリア時のみ 2000。
- 速攻点：クリア時のみ `max(0, 6000 − クリア秒 × 10)`。
- 損壊減点：総合損壊率 × 3000。
- 全項目を集計後、0 以上として最後に整数へ丸める。

180 秒・4 体・HP300・損壊20%のクリアは 10,560。180 秒・2 体・HP0・損壊20%の敗北は 1,760。未達のクリア時間を 0 秒として速攻点を与えない。時間切れ、外部ランキング送信、無限増援を追加しない。

## 11. B との契約照合補足

B の個別計画との照合で、次を契約 v1 の凍結対象へ追加する。型名は A が凍結する版を正本とし、B は仮名のまま別仕様を作らない。

- `AssetPackVersion`：原本 commit、参照ファイル hash、骨格 signature、samplingVersion。計測結果の出典が違う素材へ無検証で流用されないようにする。
- `MotionClipMeta`：clipId、カテゴリ、sourceDuration と actualDuration、通常 runtimeRate=1、startup / active / recovery、impactIndex と配分比・activeWindows、実測 effectiveReachM。既存1.5倍速素材をさらに1.5倍にしない。
- root delta と hit-volume curve は決定的な actor-local 座標で B が提供し、単位は m。C が actor pose から world 座標へ変換する。適用済み root と未適用 root の区別、区間の始終端・補間方式・軸・向きを文書化する。
- B は技内の impactIndex だけを提供する。A が actorId + attackActivationId + impactIndex から一意の ImpactId を生成する。B の配分比はダメージ額ではなく、A が総威力から各打撃の威力を決める。
- 敗北用のゲーム時間0.5秒クリップを0.25倍で実時間2秒に収める案は、終端後の表示時間で扱う。敵撃破の1.5秒スロー終了後に残りのクリップを等速継続する場合も、1.5秒のスローを延長しない。次敵参加の時点、退場姿勢の保持、残り0.125ゲーム秒の扱いは B/C と親の統合ゲートで整合させる。新しいユーザー確定仕様とは扱わない。
