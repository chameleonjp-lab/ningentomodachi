# Contract v1 candidate: ownership and composition handshake

This is the P0 boundary, not a game implementation. Freeze requires parent review and B/C/D acknowledgment. Real assets, combat, world physics, scoring, UI/effects and device acceptance remain P1 work.

## Public mapping and fixed-tick flow

- A owns `CorePort`, `createGame`, the fixed-step loop, host lifecycle, viewport publication and all runtime identities/permissions. Core is the only HP, heat, durability, scoring, encounter and result authority.
- B supplies `MotionCatalogPort` plus `AnimationPort`. Catalog metadata and samples use clip-local `impactIndex`, never runtime impact IDs. B's model/mixer internals stay private; B updates visual pose, it does not own a second renderer.
- C supplies `SpatialPort`: pose, velocity, grounded/locomotion observations, vehicle motion, geometry candidates, movement bases, scene presentation and world-to-root-CSS projection. C never regenerates A's durability ledger.
- D supplies run-scoped `UiPort`/`InputPort` and optionally the app-lifetime `HostPort`. The host factory is called once per controller; all other factories are per run. All adapters use public DTOs; no hidden global or another owner's private import is required.

`SpatialModule<Node>.renderHost` is the public model/resource composition path. A creates C before B and injects C's `ActorRenderHostPort<Node>` into `AnimationModuleContext<Node>`. The composition root binds one public generic node type (for example official Three Object3D in P1), never a private B/C type or an untyped cast. B mounts its model/skeleton by run + ActorId and retains node/mixer/material/resource ownership. C owns only the attachment/physical transform parent, scene, camera and **sole renderer**. It uses the current committed C pose before drawing a new attachment; a not-yet-positioned attachment must not flash at the origin. B's internal visual spin/pose is not overwritten by C's physical heading. Duplicate live actors, stale runs and mounts after disposal are rejected; detach is idempotent and does not dispose B resources. B pose update precedes C's one scene draw, with shared depth/camera. Reverse disposal detaches/disposes B before C's render host/scene. A factory that throws before returning a port must release its own unreturned resources.

Before each fixed tick A cuts off and delivers one immutable `GameplayInputBatch` to Core, then calls Core `beginStep`, C `step(request, catalog)`, Core `completeStep`. Core determines accepted intents and resolved events. P0 Core only exercises lifecycle/wiring and explicitly rejects attacks as not implemented; it does not adjudicate contacts.

A copies/freezes committed DTOs recursively before exposing them, including Core snapshot/events, C spatial data and host snapshots. Engine nodes never enter these DTOs. A consumer cannot mutate a published frame, and later producer mutation cannot rewrite its history. Core producers still must honor revision/authority semantics for future state; this isolation does not legitimize internal mutation without revision. Real-populated-copy performance remains a P1 measurement.

After each committed Core output, `SpatialPort.commit(output, viewport)` applies A's authoritative actor/world state and returns the collision-resolved spatial snapshot without another simulation step. A checks run/tick correspondence and gives B/C/D the same `CommittedFrame` (Core snapshot/events, C pose observations, shared viewport). B consumes C's position/facing/velocity/grounded/locomotion and A's clip/presentation state. C `render` and `project` then D `render` do not change Core state. At P1, C retains the step's resolved pose for `commit`; non-step commits synchronize authority without moving the world.

`AttackState.impactBindings` is A's immutable activation-scoped join from B `impactIndex` to A `ImpactId`. C copies that ID and the actor/activation IDs unchanged into contacts. Two actors using the same clip have distinct activation/impact identities. Consumed IDs do not substitute for this mapping. Motion sampling space/interval/root ownership is documented in `motion.ts`.

`GameSnapshot.world` is the current authoritative durability/broken/launch-permission state, not a delta inferred by C. Only `VehicleLaunchApproved`, with its stable `LaunchId` and resolved contact, authorizes a new launch. C deduplicates approval event IDs per run; `canLaunch` alone is not a launch instruction. Broken cars cannot regain permission from scene appearance. C reports vehicle poses/velocity/grounded/launch identity through `SpatialSnapshot`; A still decides damage and destruction. `HpChanged`, `ClashResolved` and launch approvals identify the accepted contact point and participating runtime impacts, not a speculative cached candidate. Vehicle contacts can have no participating attack impacts.

## Input identity, cutoff, held movement and release

One D input adapter assigns unique command IDs and positive, strictly increasing source sequences across **all** gameplay command kinds for its whole run. Do not reset that counter on pause. Arrival order may differ; A sorts at the next fixed-tick cutoff by sequence, then deterministic UTF-16 command-ID order for malformed equal-sequence ties. Sequence is chronological transport order, **not attack/jump acceptance or priority**. D must preserve competing actions, not reorder/filter them by battle rules. P1 Core receives the complete batch and owns their arbitration; P0 invents no precedence rule.

Only A may send the internal CoreCommand AssetsReady, after the successful current-generation catalog.prepare. It is absent from public input/UI GameCommand. Runtime public-route whitelists and a per-run prepared latch reject serialized readiness forgeries and premature start/advance; TypeScript alone is not the gate.

The batch identifies the upcoming tick. Only packets received before its cutoff belong to it; reentrant/later input waits for a later tick. Commands are copied/frozen when queued. A drops duplicate IDs, sequences at/below the already consumed/cancelled cutoff, stale runs and invalid movement vectors. Pause/interruption/terminal/restart/viewport-change release preempts queued gameplay. There is no render-frame input acceptance or input reservation window in P0.

`InputPort` starts disabled and obeys A `setGate`; global running permission is distinct from each actor's Core-owned `actions`. D can read the latest snapshot through its context and displays allowed/reason directly, never from a heat threshold. At a state/terminal change A closes the gate and releases input. The adapter's `releaseAll` clears D pointer state and must not echo packets while A is releasing it. `InputsReleased` tells Core to clear retained intents; `MovementSessionEnded` clears retained movement for that session.

At pointer gesture start, including zero displacement, D calls `context.movement.begin(uniqueGestureSessionId)` **synchronously**. A asks C for a basis and retains an immutable copy. Right/depth are C-provided normalized orthogonal world directions; basis revision is C-owned and distinct from viewport revision. Every move carries the session ID and captured basis revision. Its x/z components are held-basis components: positive x is screen-right and positive z is screen-up/away-from-camera, not world axes. D maps upward swipes to positive z. Each component is in [-1,1], Euclidean length at most 1; C applies the held basis, never recaptures the current camera at the first nonzero tick. Zero means held/no displacement, not release.

On release/cancel D calls `end`; A immediately cancels unflushed movement for that session and tells Core/C it ended. Session IDs cannot be reused in a run, even if the OS reuses a pointer ID; append a gesture counter. All-release cancels the queue, advances its known sequence cutoff, ends every basis and tells Core to clear retained input. Old contexts cannot begin sessions or read/control a successor run. The new run gets new IDs and a new source sequence scope.

## Snapshot, event and presentation authority

Snapshot revision is monotonic and separate from simulation tick; settings, pauses, display quality and presentation clocks can change without a tick. Each run's events have explicit increasing sequence, are emitted in that order, and have opaque unique IDs. Consumers deduplicate by run + event ID/sequence and discard stale runs; never parse IDs. Event consumption is independent of snapshot revision: a new event can accompany an unchanged snapshot. Actor IDs are never reused within a run. Ordered `OpponentChanged` plus the committed current opponent tells D when to cancel an old opponent's effects.

HP loss and healing remain distinct ordered events even in one tick: do not infer lost HP from the final net snapshot. Zero-difference clashes do not require fake HP loss. Permissions expose explicit reasons (for example heat 6.5 allowed versus heat 0 with continuing cooling lock). Results expose both street/vehicle destruction rates directly; D never derives them from a penalty.

`present(elapsed)` accounts unscaled elapsed once per accepted frame: active-real advances only during running/unpaused gameplay, including sub-tick frames; fixed steps advance game time, not active-real. Draining already accepted backlog with elapsed=0 does not advance real time. Ready, pause, background and terminal do not advance the cooling clock. Presentation can continue after terminal separately.

The browser uses an A/controller continuity epoch covering every phase/pause-reason transition, including pause+resume between RAFs. Policy is **conservative discard of the entire unmeasured RAF interval crossing a transition**, not precise partial-active accounting; up to that interval's active portion is intentionally uncounted. The next frame establishes a fresh baseline. Ordinary uninterrupted long-frame elapsed is never clamped/dropped, and already accepted fixed-step/sweep backlog survives same-run pause/resume without processing during pause. Initial start/new/replaced/disposed runs reset their own accumulator; paused wall time is never added on resume. This is separate from input cancellation, which still discards queued/held input on pause.

Presentation stages (`opponent-defeat`, `defeat-slow`, `clear-slow`, `fade`, `results`) and deadlines are A-owned. `startedAt`/`endsAt` use **PresentationTimeMs**: unscaled elapsed presentation time, stopped for all pause reasons/background/interruption. This clock can continue after terminal result latching; game/scoring/heat clocks must remain frozen then. It is distinct from game-time `finalizedAt` and the gameplay active-real cooling clock. Core determines stage/deadline transitions; D compares this clock for interpolation but must not start a second progression timer. Low-fps elapsed can pass a deadline in one frame without changing finalized result/score/heat. P0's test-only scripted authority demonstrates these DTOs; actual terminal progression and 1.5/2-second rules are P1, not implemented in production Core.

## Surviving host, UI requests and interruptions

`HostPort` receives title/loading/ready/playing/error/results/disposed state independently of run resources, subscribes to unique-ID `HostRequest`s and survives initial load failure or cancellation. Prepare/retry goes through this path even when there is no active run. Repeated request IDs are ignored; repeated pending prepares/retries do not create parallel runs. Return-to-title/cancel aborts the old run and disposes its ports, not the host. Results-to-title/new-run is the same public path.

A run UI gets `UiModuleContext.request(HostRequest)` for start/settings/return-to-title/retry. Ordinary Core controls use `CommandRequested` with the current run ID; input packets use the separately gated `InputPort`. Old UI callbacks cannot affect a successor. The persistent shell's own subscriber is app-scoped. WebGL/context-loss adapters use the existing `PauseRequested(reason: 'interruption')`; visible/recovered does not remove interruption automatically, and explicit resume is required. Unrecoverable adapter failure uses error/retry, not invented HP/game state.

`bootstrap(..., { autoPrepare: false })` supports title-first composition. Default auto-prepare remains available for a loading-first host. Initial `ready` rejects with the original loading error but the shell/controller/RAF/listeners remain alive for retry. Error/title/loading frames do not advance simulation; a fresh run resets the timestamp. Only explicit binding disposal removes listeners and disposes the host/controller. Every independent RAF/lifecycle/viewport/game cleanup action is attempted even if another throws; errors are aggregated and repeat disposal is idempotent. No actual D host is supplied in P0.

## One viewport authority and projection handshake

A's controller owns `updateViewport`; B/C/D get the same read-only `ViewportReader`. Each publication creates one immutable revision with root width/height, client-space root offsets, device-pixel ratio and safe-area CSS insets. Host/browser integration measures the actual render root and publishes after resize, rotation, root layout/offset or safe-area changes. It must not use independently incremented C/D counters. An injected `BrowserHost.viewport` source is read/subscribed by bootstrap (or passed through `createBrowserHost`); cleanup unsubscribes it. The source is injected so P0 does not implement a D layout or C renderer.

Projection points are **root-local CSS pixels**, not device pixels. D converts its own DOM client anchors by subtracting the same root offsets. C projects only confirmed resolved-contact world points (or explicitly supplied C proxies), stamps the frame's shared viewport revision, and returns null when unavailable. D accepts visible origins only for matching run/event/actor and current viewport revision, otherwise skips the flight; it still consumes HP/red-loss changes. Offscreen/unprojectable is never replaced with a fake central hit. D alone measures its bar/absorption anchors; those DOM details do not enter Core.

## CI evidence policy

The final aggregate requires each job's named log, contracts/unit/integration JSON+JUnit XML, and build index, all nonempty and manifest-listed. It checks all artifact files exhaustively (no extra unhashed payloads), exact identities and SHA-256 bytes. Actual structured Vitest reports must have at least one executed passing assertion, consistent totals/results and zero failed, pending/skipped or todo tests. P0 permits no skip/todo exclusions. Producers still preserve incomplete/failing logs for diagnosis; job status and the aggregate remain fail-closed. Synthetic policy tests run the actual package command/reporters on passed, skip-only and todo-only suites; successful report JSON/XML is not invented. Remote GitHub execution remains unperformed.

## Acceptance evidence and limits

Headless synthetic cases live in `host-services.test.ts`, `committed-boundaries.test.ts`, browser bootstrap/core tests and the existing motion/CI tests. The scripted test Core is explicitly not combat/world/UI product code. These tests establish information transport and ownership only, not real curve baking/CCD, browser/Safari/WebGL, touch layout, real UI/effects, gameplay timing or remote GitHub execution. All future owners still require the merged common main SHA before starting P1.
